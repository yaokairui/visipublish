# channel-adapters Specification

## Purpose
定义渠道发布契约：以统一的适配器接口（登录 / 上架 / 下架 / 状态检查）隔离不同平台的差异，使上架助手可插拔地接入模拟后台、官方 API 或浏览器自动化等发布通道，并约定登录态、重试、幂等与状态可观测行为。
## Requirements
### Requirement: 渠道适配器契约

系统 SHALL 通过统一的渠道接口执行发布相关操作（登录 / 上架 / 下架 / 状态检查）；不同渠道各自实现该接口，调用方不感知平台差异，发布结果以结构化数据返回。

#### Scenario: 发布到已配置渠道
- **WHEN** 用户确认上架且所选渠道可用
- **THEN** 系统通过该渠道的适配器完成发布，并返回结构化结果（成功 / 失败、步骤、消息）

#### Scenario: 渠道不可用提前拦截
- **WHEN** 所选渠道不可用（未配置 / 未登录 / 服务不可达）
- **THEN** 系统在发布前给出明确错误提示，不执行发布

### Requirement: 登录态与会话管理

系统 SHALL 支持渠道登录态管理：API 渠道使用授权凭证（token / 密钥），RPA 渠道使用持久化浏览器会话（Cookie / profile）；凭证失效时须终止发布并提示重新授权。

#### Scenario: 凭证失效
- **WHEN** 渠道凭证失效或登录态过期
- **THEN** 系统终止发布并提示用户重新登录或授权

### Requirement: 上架与下架

系统 SHALL 支持按商品记录执行上架与下架，下架通过同一渠道契约完成，并更新记录状态。

#### Scenario: 下架商品
- **WHEN** 用户对某条已上架记录执行下架
- **THEN** 系统通过该渠道的适配器完成下架并更新记录状态

### Requirement: 重试、回读校验与幂等

系统 SHALL 对发布关键步骤提供自动重试与回读校验；同一条记录的重复提交不得产生重复商品。

#### Scenario: 关键步骤失败重试
- **WHEN** 发布过程中某关键步骤失败
- **THEN** 系统自动重试至配置次数上限，仍失败则标记该条失败并保留留档（截图 / 日志）

#### Scenario: 重复提交幂等
- **WHEN** 同一条记录因网络抖动等原因被重复提交
- **THEN** 渠道侧以唯一标识去重，不产生重复商品

### Requirement: 任务状态可观测

系统 SHALL 为每条发布任务维护状态（待发布 / 发布中 / 成功 / 失败），并在界面展示逐条状态与失败原因。

#### Scenario: 查看批量发布状态
- **WHEN** 用户查看批量发布结果
- **THEN** 界面展示每条记录的最终状态与失败原因
