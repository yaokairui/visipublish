## Purpose

定义批量商品处理的行为契约：一次上传多张商品图片后，逐张独立完成识别与规则生成，形成可编辑、可勾选的审核队列，并支持按勾选顺序批量发布、单条失败隔离与进度反馈。

## ADDED Requirements

### Requirement: 批量上传与逐图生成

系统 SHALL 支持一次上传多张商品图片（jpg / jpeg / png / webp），并为每张图片独立执行识别与规则生成，产出独立的商品记录；单张图片失败不得中断整批。

#### Scenario: 上传多张图片并生成
- **WHEN** 用户一次上传 N 张可解析的商品图并触发生成
- **THEN** 系统为每张图生成一条独立的商品记录（标题 / 类目 / 属性 / 提示词），列表总数等于成功识别的图片数

#### Scenario: 批内单张图片失败
- **WHEN** 批内某张图片不可解析或识别失败
- **THEN** 系统跳过该张并标记失败原因，其余图片继续生成，整批不中断

### Requirement: 批量审核与编辑

系统 SHALL 以可编辑列表展示全部生成结果；用户可逐条修改标题 / 类目 / 属性，可对单条执行「重新生成」以轮换核心卖点，并可勾选待发布的上架项。

#### Scenario: 批量编辑生效
- **WHEN** 用户在审核列表中修改某条的标题与属性
- **THEN** 发布时使用修改后的值，且其余条目不受影响

#### Scenario: 单条重新生成
- **WHEN** 用户对某条点击「重新生成」
- **THEN** 仅该条的卖点 / 标题 / 提示词轮换更新，其他条目保持不变

#### Scenario: 仅发布勾选项
- **WHEN** 用户勾选部分条目并确认发布
- **THEN** 仅被勾选的条目进入发布流程

### Requirement: 批量发布与失败隔离

系统 SHALL 按勾选顺序依次发布，提供进度反馈；单条失败不影响后续条目，最终汇总展示逐条成功 / 失败结果。

#### Scenario: 批量发布成功
- **WHEN** 用户确认发布 N 条勾选项
- **THEN** 系统逐条发布并展示总体进度与逐条结果

#### Scenario: 单条失败隔离
- **WHEN** 批内某条发布失败
- **THEN** 系统记录该条失败原因并继续处理后续条目，最终汇总成功与失败清单
