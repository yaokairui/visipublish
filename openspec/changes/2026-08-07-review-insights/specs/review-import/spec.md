## Purpose

定义评价数据导入与标准化的行为契约：接受商家后台导出的 Excel/CSV 或粘贴文本，通过列别名映射与清洗去重，输出统一的评价明细行（内容 / 星级 / 日期 / 商品 / 平台 / 店铺），保证下游情感分析与痛点挖掘可安全消费。

## ADDED Requirements

### Requirement: 文件导入与列映射

系统 SHALL 支持上传 `.xlsx` / `.xls` / `.csv` 评价文件，识别评价内容、星级、日期、商品、平台、店铺等列；列名同时支持中文（如「评价内容」「星级」）与常见英文别名（如 `content` / `rating`），无法识别的列忽略、缺失列使用默认值。

#### Scenario: 上传商家后台导出的评价
- **WHEN** 用户上传一份含「评价内容 / 星级 / 日期 / 商品」列的 Excel
- **THEN** 系统导入全部有效行，并为缺失的平台/店铺列填充默认值「未知平台 / 未知店铺」

#### Scenario: 列名缺失
- **WHEN** 文件中没有可识别的「评价内容」列
- **THEN** 系统拒绝导入并提示缺少必需列，不产生部分数据

### Requirement: 星级归一

系统 SHALL 将星级归一为 1-5 的数值：支持数字（5 / 4.5）、星号串（`★★★★★`）、emoji（`⭐⭐⭐`）与文本（「好评 / 中评 / 差评」）形式，无法识别时按 3 星处理。

#### Scenario: 混合星级格式
- **WHEN** 同一文件里星级同时出现数字、星号串与 emoji
- **THEN** 系统全部归一为 1-5 数值，且 1-2 星判为差评、4-5 星判为好评

### Requirement: 清洗与去重

系统 SHALL 过滤空内容行，并对「内容 + 日期 + 商品」完全相同的行去重，去重后保留首次出现的那条。

#### Scenario: 重复导入
- **WHEN** 同一文件重复导入或文件内含重复行
- **THEN** 系统去重后导入，并在结果中报告原始行数与有效行数

### Requirement: 粘贴文本解析

系统 SHALL 支持把粘贴的多行文本解析为评价：每行一条，可选 `[5星]` / `[1星]` 前缀或 `星级：` 分隔符；无星级前缀时按 3 星处理。

#### Scenario: 粘贴带星级前缀的文本
- **WHEN** 用户粘贴「[1星] 物流太慢了」等多行文本
- **THEN** 系统按行解析并正确读取星级
